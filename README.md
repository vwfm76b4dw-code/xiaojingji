# 小鲸记单词

> 一个把「复习时机」交给算法决定的背单词微信小程序（SM-2 间隔重复）。
> 参赛作品：2026 年北京市师生数字素养提升实践活动 · 人工智能作品征集。

用微信扫码即可使用：**无需注册、无需登录**，数据只存在你自己的手机里。

---

## 它解决什么问题

背单词最典型的失败模式不是"不努力"，而是**努力用错了地方**：

- 今天背 50 个，第二天忘 30 个；
- 于是从第一个词重新背，大量时间花在已经很熟的词上；
- 那些"快要忘掉"的词，恰恰因为没被想起来，最终彻底遗忘；
- 反复几次后得出结论"我记性不好"——但问题出在**复习时机**，不在记忆力。

这个困境有一个关键特征：**它是可计算的**。遗忘曲线的结论是，在"即将遗忘但还没完全忘掉"的那一刻复习，记忆保持时间会显著延长。而"最佳复习时刻"取决于这个词对学习者的难度和上次复习的效果——这两个因素都能被记录、被追踪、被计算。

所以背单词的效率问题，本质上是**调度问题**。

## 技术核心：SM-2 调度引擎

每个单词维护三个数：

| 变量 | 含义 | 初始值 |
|---|---|---|
| `EF` | 难度系数（Easiness Factor） | 2.5 |
| `reps` | 连续答对次数 | 0 |
| `interval` | 当前复习间隔（天） | 0 |

每次作答三档评价，映射到 SM-2 的 0–5 分制：

| 档位 | q 值 | 效果 |
|---|---|---|
| 认识 | 5 | EF 上升，间隔按规则延长 |
| 模糊 | 3 | EF 下降，间隔仍延长但变慢 |
| 不认识 | 1 | 间隔重置为 1 天，重新开始 |

间隔规则：`reps=1` → 1 天，`reps=2` → 6 天，之后 `round(interval × EF)`。
实测间隔序列：**1 → 6 → 17 → 49 → 147 天**。

EF 更新公式（原始 SM-2）：
```
EF' = EF + (0.1 − (5−q) × (0.08 + (5−q) × 0.02))
```
EF 下限 1.3，防止难度系数无限下降。

> 算法实现在 `miniprogram/utils/sm2.js`，配套验证脚本见 `tools/verify-sm2*.js`。

## AI 能力

AI 在本作品里的定位很明确：**降低使用成本，不替代记忆过程**。

| 能力 | 怎么用 | 失效时 |
|---|---|---|
| 自然语言批量录入 | 粘贴一段话（如"abandon 遗弃，abundant 丰富的"），自动解析成结构化词条 | 引导改用批量粘贴（纯本地解析） |
| 例句 / 词根生成 | 单词一键生成初中生活化例句、词根拆解 | 回退到随包预置的 60 词例句库 |
| **发音评测** | 按住读单词，识别后与目标词比对，给出"读得不错 / 再练练 / 读错了" | 降级为"先自己读一遍，再看答案" |
| **端上词义检索** | 回答"课本里学校用品有哪些词"这类问题 | 完全离线可用（端上算法，不联网） |

**语音识别为什么必须走云函数**：把声音变成文字需要声学模型，端上跑不动。Key 只存在云函数的**环境变量**里，不进代码、不进前端——小程序前端可被反编译，前端放 Key 等于公开泄露。

**端上检索**是自己实现的融合排序算法（Damerau-Levenshtein + Jaro-Winkler + Dice 系数 + 音素 + 辅音骨架 + 押韵），配合 23 个主题索引，所以离线也能答问题。

## 离线优先的架构

```
界面层（9 个页面）
   ↓ 用户反馈
核心逻辑层（SM-2 调度 / 存储 / 统计 / 检索）  ← 零外部依赖，断网可用
   ↓
云函数层（AI 增强，可插拔）                    ← 去掉它作品依然完整
```

- **随包预置 294 个真人发音**（16kbps 单声道，约 1MB），离线可听、零延迟、零流量成本
- 复习、统计、检索**全部本地完成**，数据不出设备
- 云函数只在「AI 增强」环节被调用，不可用时自动降级，核心链路不受影响

## 本地运行

1. 用[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)打开 `miniprogram/` 目录
2. 在 `project.config.json` 里把 `appid` 换成你自己的小程序 AppID
3. 编译即可运行——**核心功能不需要任何配置**

### 启用 AI 能力（可选）

复制 `cloudbaserc.template.json` 为 `cloudbaserc.json`，填入自己的密钥，把两个云函数部署到微信云开发，然后在云开发控制台配置环境变量：

| 云函数 | 环境变量 |
|---|---|
| `asrProxy` | `ASR_PROVIDER=tencent`、`TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY`、`TENCENT_REGION` |
| `aiProxy` | `GLM_API_KEY`、`GLM_MODEL` |

不配也能用——所有 AI 功能都有降级路径。

```bash
bash tools/check_all.sh          # 13 道门禁，全绿才允许交付
```

## 设计取舍

**为什么把 SM-2 的六档评分简化成三档？**
依据是初中生的实际使用场景，不是技术难度。六档（完全忘记 / 模糊 / 勉强 / 犹豫 / 记得 / 秒答）需要使用者对自己的记忆状态做精细区分，而初中生在复习时通常只能给出"会 / 不确定 / 不会"这三种判断。硬套六档会让用户为了填满档位而乱选，反而污染调度数据。

**为什么手写图表而不用图表库？**
统计页需要五种基础图形，引第三方图表库要过 npm 构建、体积翻倍、默认皮肤还要花力气覆盖。手写不到 300 行且完全可控——当需求足够简单时，"自己写"往往比"引依赖"更划算。

**为什么日期处理不用 `toISOString()`？**
它会先把本地时间转成 UTC。中国用户在北京时间清晨或深夜使用时，日期会错开一天，导致复习队列异常。本项目用 `utils/date.js` 按本地时区取年月日。

## 隐私

- 单词数据与复习记录**只存在本机**，不上传服务器
- 不采集姓名、学号、地理位置等任何身份信息，不设账号体系
- 唯一离开设备的内容是语音评测时的一段录音——经云函数转文字后**立即从云端删除**，不保存、不关联身份
- 调用大模型时只发送待解析的单词文本
